# 로드맵 (향후 구현 아이디어)

현재는 구현하지 않음. 검증/여건 갖춰지면 진행.

## 1. 적응형 전략 라우팅 (Champion Selection) — 우선 관심
**개념**: 3개 전략(A 공시모멘텀 / B 거래량선행 / C 역추세)을 계속 섀도우 paper-trade 로 돌려 성과를 측정하고,
**실제 매매는 "그 시점 가장 성과 좋은 전략(챔피언)"의 신호만** 따라간다. 시장 국면이 바뀌면 챔피언도 유동적으로 교체.

**현재 구조와의 적합성** (이미 토대 있음):
- 전략은 `TradingStrategy` 인터페이스로 플러그인화 + 3개 동시 섀도우 실행
- 전략별 성과 측정: `strategy-report`, `exit-timing`, `outcome-analysis`
- 추가 필요: ① `ChampionSelector`(롤링 성과로 챔피언 선정) ② 주문 실행기(챔피언 신호만 매매)

**확정해야 할 설계점**:
1. "승자" 기준 — 평균수익률 / 승률 / 기대값(승률×평균이익) / 위험조정(수익÷변동성) 중 무엇 + 롤링 윈도우(최근 N건 또는 N일)
2. 최소 표본 게이트 — 소수 표본으로 챔피언 선정 금지(예: 전략당 ≥30건)
3. 교체 히스테리시스 — 매일 노이즈로 뒤집히지 않게, "기존 챔피언 대비 마진 이상 + 일정 기간 지속" 시에만 교체
4. 콜드 스타트 — 데이터 부족 구간: 무매매 / 균등 / 기본전략 중 선택
5. 리스크 관리는 라우팅과 별개로 항상 적용

**주의**: "최근 성과 좇기"는 노이즈 과적합 위험 → 2·3번(표본 게이트·히스테리시스)이 핵심.

## 2. 자동매매 (주문 집행) — 1번의 선행/병행 요소
- KIS 주문 API(매수 `TTTC0802U`/매도 `TTTC0801U`, hashkey, 계좌, 잔고조회) 연동
- **반드시 모의투자 계좌 우선** → 검증 후 소액 실전
- 리스크 관리 필수: 종목당 투자금, 일일 최대손실 한도, 중복주문 방지, 미체결·부분체결·주문거부 처리, 긴급정지(kill switch)
- **전제**: 전략이 paper-trade 로 수익성 검증된 후에만 (현재 데이터 누적 단계)

## ✅ 구현 완료 (참고)
- **국면별(상승장/하락장) 성과 분석** — 진입시점 해당시장 지수 등락률을 `TradeOutcome.entry_market_change` 에 저장, `outcome-analysis` 의 `byMarketRegime` 로 상승장/하락장 구간별 승률·평균수익 제공. (2026-06-25 구현, 데이터 누적 중)
